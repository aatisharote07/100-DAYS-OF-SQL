# Day 74: SQL Challenge - Aggregate Functions (Generating Subtotals with ROLLUP)

## 📌 Business Scenario
A Sales Director is requesting a comprehensive revenue report. They want to see the total revenue broken down by `region` and `product_category`. 

However, instead of just the granular rows, they *also* want **Subtotal** rows for each region, and a single **Grand Total** row at the very bottom of the report. Historically, analysts would write three separate queries and `UNION ALL` them together. 

Modern SQL provides a much more elegant solution: the `ROLLUP` extension for the `GROUP BY` clause.

---

## 🗄️ The Schema

### Table Structure & Sample Data

```sql
-- Create Sales Table
CREATE TABLE regional_sales (
    sale_id INT PRIMARY KEY,
    region VARCHAR(50),
    category VARCHAR(50),
    revenue DECIMAL(10, 2)
);

-- Insert Sample Data
INSERT INTO regional_sales VALUES
(1, 'North', 'Electronics', 500.00),
(2, 'North', 'Electronics', 300.00),
(3, 'North', 'Furniture', 400.00),
(4, 'South', 'Electronics', 600.00),
(5, 'South', 'Furniture', 200.00),
(6, 'South', 'Furniture', 100.00);
```

---

## ❓ The Question
Write an SQL query using `ROLLUP` to generate the revenue report. 

The report should include the granular Region/Category totals, the Subtotals for each Region, and the overall Grand Total. Because `ROLLUP` generates `NULL` values for the aggregated dimensions, use `COALESCE()` to replace the `NULL` region with `'GRAND TOTAL'` and the `NULL` category with `'REGION SUBTOTAL'`.

Return the `region`, `category`, and `total_revenue`. Order the results logically.

---

## 💡 The Solution

```sql
SELECT 
    -- Clean up the NULLs generated by the ROLLUP grouping
    COALESCE(region, 'GRAND TOTAL') AS region,
    COALESCE(category, 'REGION SUBTOTAL') AS category,
    SUM(revenue) AS total_revenue
FROM regional_sales
-- Generate the granular rows, the subtotals, and the grand total
GROUP BY ROLLUP (region, category)
ORDER BY 
    -- Ensure the GRAND TOTAL sorts to the very bottom
    CASE WHEN region IS NULL THEN 1 ELSE 0 END, 
    region, 
    CASE WHEN category IS NULL THEN 1 ELSE 0 END,
    category;
```

---

## 📝 Explanation
- **The Problem with Standard `GROUP BY`**: A standard `GROUP BY region, category` will compress the 6 raw rows into exactly 4 granular rows (North Electronics, North Furniture, South Electronics, South Furniture). It will *not* calculate how much the North made in total.
- **The Power of `ROLLUP`**: By changing it to `GROUP BY ROLLUP(region, category)`, the database automatically generates the standard 4 rows, **plus** a subtotal row for 'North' (where category is set to `NULL`), **plus** a subtotal row for 'South' (where category is set to `NULL`), **plus** a grand total row for the entire table (where both region and category are `NULL`). 
- **The `COALESCE` Polish**: Because those extra summary rows contain `NULL`s in the grouping columns, we wrap them in `COALESCE()` to replace the `NULL`s with human-readable labels like `'GRAND TOTAL'`.
- **The `ORDER BY` Trick**: To ensure the summary rows appear in a logical hierarchy (Subtotals at the bottom of their respective regions, and Grand Total at the very bottom of the report), we use a `CASE` statement in the `ORDER BY` clause to push the `NULL`-generated rows down.
