# Day 53: SQL Challenge - Window Functions (Calculating Percentage of Total)

## 📌 Business Scenario
A regional sales director is reviewing Q3 performance. They don't just want to see the total revenue generated by each sales region; they want to know the **Market Share** — what percentage of the company's total overall revenue did each region contribute?

To achieve this, we need to compare a grouped aggregate (regional total) against a grand aggregate (company total) in the same query. Window functions provide the most elegant way to solve this without writing clunky subqueries or cross joins.

---

## 🗄️ The Schema

### Table Structure & Sample Data

```sql
-- Create Sales Table
CREATE TABLE region_sales (
    sale_id INT PRIMARY KEY,
    region VARCHAR(50),
    revenue DECIMAL(10, 2)
);

-- Insert Sample Data
INSERT INTO region_sales VALUES
(1, 'North America', 50000.00),
(2, 'North America', 25000.00), -- NA Total: 75,000
(3, 'Europe', 40000.00),
(4, 'Europe', 10000.00),       -- EU Total: 50,000
(5, 'Asia Pacific', 60000.00), -- AP Total: 60,000
(6, 'Latin America', 15000.00);-- LA Total: 15,000
-- Grand Total Revenue: 200,000
```

---

## ❓ The Question
Write an SQL query to calculate the total revenue for each region, and then calculate the percentage that region contributed to the grand total revenue. 

Return `region`, `regional_revenue`, and `pct_of_total` (rounded to 2 decimal places). Order the results by `pct_of_total` in descending order.

---

## 💡 The Solution

### Method 1: CTE + Window Function (Cleanest to Read)
```sql
WITH RegionalTotals AS (
    -- Step 1: Calculate the standard grouped totals
    SELECT 
        region, 
        SUM(revenue) AS regional_revenue
    FROM region_sales
    GROUP BY region
)
SELECT 
    region,
    regional_revenue,
    -- Step 2: Use an empty OVER() clause to get the grand total across all rows
    ROUND((regional_revenue / SUM(regional_revenue) OVER ()) * 100, 2) AS pct_of_total
FROM RegionalTotals
ORDER BY pct_of_total DESC;
```

### Method 2: Direct Aggregation + Window Function (Advanced)
```sql
SELECT 
    region,
    SUM(revenue) AS regional_revenue,
    -- Nesting a standard aggregate inside a window aggregate!
    ROUND((SUM(revenue) / SUM(SUM(revenue)) OVER ()) * 100, 2) AS pct_of_total
FROM region_sales
GROUP BY region
ORDER BY pct_of_total DESC;
```

---

## 📝 Explanation
- **The Empty `OVER()` Clause**: By appending `OVER ()` to an aggregate function like `SUM()`, you transform it into a window function. Because the parenthesis are empty (no `PARTITION BY`), it calculates the sum over the *entire* result set.
- **Method 1 (CTE approach)**: This separates the logic. The CTE handles the `GROUP BY` to get regional totals (e.g. NA: 75k). The outer query then takes that 75k and divides it by the grand total (200k) provided by `SUM(regional_revenue) OVER ()`. 
- **Method 2 (Nested approach)**: This does it all in one pass. `SUM(revenue)` gives the grouped total per region. `SUM(SUM(revenue)) OVER ()` tells the engine to take those grouped sums and sum them up again across the entire window, yielding the grand total.
- **The Output**: North America (75k / 200k) yields `37.50%`, Asia Pacific yields `30.00%`, Europe yields `25.00%`, and Latin America yields `7.50%`.
